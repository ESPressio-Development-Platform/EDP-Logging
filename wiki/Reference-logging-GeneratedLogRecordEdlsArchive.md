# GeneratedLogRecordEdlsArchive — implementation reference

**Classification:** Public optional governed-record archival adapter. **Owning header:** [src/logging/GeneratedLogRecordEdlsArchive.hpp](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/feature/logging-v1/src/logging/GeneratedLogRecordEdlsArchive.hpp). **Version:** 0.1.0, source branch feature/logging-v1. This page describes implementation and owner requirements; it does not replace normative ./docs contracts.

## Responsibility and boundaries

Emits the generated-schema-qualified fifteen-field record through EDP-Serialisation canonical CBOR and Logging framing into the existing immutable EDLS successor/rolling protocol. The original source coordinate and issued root TypeIdentifier are preserved.

## Resource, failure and lifecycle invariants

Do not serialize the private native owned-argument arena as a wire record. A failed conversion, full slot, or uncertain publication must remain a typed refusal and must not advance a durable acknowledgement.

## 12 November 2026 — complete typed one-shot EDLS publication results

**Exact source:** [`GeneratedLogRecordEdlsArchive.hpp`](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/8d2b307a8a1db1aa5596abc904cd0da1f3c032cd/src/logging/GeneratedLogRecordEdlsArchive.hpp). `GeneratedEdlsPublishStatus : uint8_t` has: **Published (0)**, a complete **non-strict** EDLS successor is verified under the chosen FileStorage profile (not a separate PowerLoss NVS ACK); **SourceIdentityMismatch (1)**, record Device/Incarnation disagrees with archive owner; **ProjectionRejected (2)**, generated EDP-Localisation/EDP-System typed LogRecord projection could not be validated; **CborRejected (3)**, owner EDP-Serialisation Measure or Serialize failed canonical TypedEnvelope; **CborCapacityExceeded (4)**, exact measured bytes exceed caller-owned CBOR scratch or selected payload budget; **FramingRejected (5)**, bounded complete EDLG frame could not be produced; **ArchiveRejected (6)**, checked successor publisher failed/unconfirmed physical archive state.

`GeneratedEdlsPublishOutcome<N>` has `Status` (above, default ProjectionRejected), `Projection : GeneratedLogRecordProjectionOutcome` (original generated field/first-failed-argument evidence), `Archive : EdlsProtectedRollingOutcome<N>` (native semantic checked publication), `CborBytes` (exact encoded CBOR length, zero until measured/written) and `EdlgBytes` (exact complete CRC frame length). `IsPublished() const noexcept` is true **only** for Published. Template `N` must match the archive's physical path count, and must not be mistaken for number of records or a guaranteed retention duration.

`PublishGeneratedLogRecordToProtectedEdlsWithScratch<TMessageSchema,TProtectedSlots,TMaximumPayload,TMaximumSegment,TWidth,TParameters...,TMaximumArguments,TArgumentBytes,TPhysicalSlots,TStorage>` borrows a complete typed `BasicLogRecord`, caller-owned `GeneratedLogRecordWireProjection`, positional re-encoding scratch, bounded CBOR scratch, separate EDLG frame scratch, app-selected FileStorage provider, exact FilePathView path array, expected DeviceIdentifier/Incarnation and disjoint full archive scratch. The generated message/schema and ordered `TParameters...` select the existing Localisation/Serialisation Type contract; `TWidth` fixes attempt width; `TMaximumArguments,TArgumentBytes` bound source ownership; `TMaximumPayload,TMaximumSegment` cap wire and physical bytes; `TPhysicalSlots=TProtectedSlots+1` guarantees one unprotected successor; `TStorage` supplies existing qualified FileStorage. It validates source identity, strictly projects fields, measures and serializes canonical CBOR, writes one CRC-protected EDLG frame, then delegates the *existing* immutable EDLS rolling successor algorithm; any failure reports its actual stage rather than claiming publication. The wrapper `PublishGeneratedLogRecordToProtectedEdls` uses stack-backed bounded scratch for its convenience overload, so large WROOM workloads should provision stable external scratch and use WithScratch. No new codec, task, retention policy or KeyValueStorage ACK is owned here; use the separate strict acknowledged adapter for real durable completion.
