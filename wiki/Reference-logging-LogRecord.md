# LogRecord — permanent System semantic type identity (G4)

Opt-in `logging/LogRecord.hpp` declares a direct immutable compile-time
`System::TypeIdentifier`:
`00 00 01 00 00 00 00 01`.
The 24-bit Authority `0x000001` belongs to ESPressio Development
Platform Core; the 40-bit local value `0x0000000001` belongs
permanently and exclusively to `Logging::LogRecord`. This allocation
was authorised 2026-10-17 and published in the owner
[System registry](https://github.com/ESPressio-Development-Platform/EDP-System/blob/main/docs/TYPE-IDENTITY-REGISTRY.MD).

`System::IdentifiedType<Logging::LogRecord>` is true, and
`System::TypeIdentifierOf<Logging::LogRecord>` reads identical
eight-byte storage. The actual `LogRecord` now supplies 15
compile-time `System::FieldBinding` members, one per approved
FieldId 0..14; `System::SchemaType<Logging::LogRecord>` is true.
`BasicLogRecord<AttemptSequenceWidth,MaxArguments,ArgumentBytes>`
selects a 16/32/64-bit attempt width and bounded owned in-memory
arguments without changing semantic Type identity. Field 11 has the
issued typed Clock provenance pair (projection and quality); Field 14
is an issued uint8 field whose only permitted v1 value is zero.
`BasicLogRecord` is the **owned structural source representation**,
not itself a `Serialisation::SerialisableType`: the separate
[`GeneratedLogRecordWireProjection`](Reference-logging-GeneratedLogRecordWireProjection)
uses its permanent TypeIdentifier and all fifteen FieldIds with
Localisation-generated, typed Field 13 parameters to satisfy the
existing Serialisation CBOR/JSON TypedEnvelope contracts. The actual
optional worker and strict NVS-acknowledged EDLS application fixtures
are documented separately; their finite qualified profiles must not
be mistaken for every source/SDK combination.

Identity persistence is independent of library version (all remain
0.1.0), message StringIdentifier, transport or Mesh participation.

## Fail-closed source validation (current contract; original 2026-10-17 gate)

`ValidateLogRecord` rejects unissued/invalid typed Field 11 provenance
with `InvalidTemporalProvenance`, and nonzero (reserved) Field 14
with `ReservedRecordFacts`, before accepting wire projection. Earlier
2026-10-17 placeholder names and limitations were superseded by the
approved child-field wire contracts of 19 October. In the absence of a synchronized coordinate, the
`EDP-Clock::SynchronizationUncertainty` must remain saturated/unknown;
zero uncertainty falsely implies precision and is rejected as
`InvalidSyncEvidence`. Legal monotonic-only records remain supported.
These checks do not allocate an on-wire vocabulary, provide a coherent
upstream Clock capture, or make the root `SerialisableType`.
The host `LogRecordIdentityTests` covers the new failure outcomes.


## Generated schema source assembly (G3/G4 source capture)

The optional `LogRecordSourceAssembly.hpp` captures owner-generated
message identity, fingerprint, strong source identity and qualified
Clock values with bounded exact-width scalar positional values.
Destination mutation happens only after successful validation and all
argument copies. Invalid input, occupied output and insufficient
finite argument bytes preserve the prior destination. A successful
source record remains structural: to produce a complete TypedEnvelope,
the caller selects the generated 15-field wire projection and the
EDP-Serialisation codec; source assembly alone is not a codec.


The source-assembly constructor now derives the fingerprint from
`GeneratedMessageSchema::OwningContract` (generated by Localisation),
rejects non-coherent unavailable ClockEra or falsely precise missing
synchronized uncertainty, and never asks for a separately selected
catalogue fingerprint.


The bounded source capture now supports owner-backed UTF-8, Bytes,
System TypeIdentifier, DeviceIdentifier and the added exact one-byte
FieldIdentifier private source kind. It does not confuse semantic
FieldIdentifier with a generic U8 argument or public wire tag.


## 2026-10-19 — approved G4 child-field wire

Field 11 is an ordered two-element pair of EDP-Clock owner enums,
`ClockCorrelationProjectionStatus` and `TemporalQualityAssessment`.
Field 14 is exactly one uint8 whose only supported v1 value is zero;
nonzero and unknown enum values fail closed. The approved
[G4 child wire reference](../docs/G4-APPROVED-FIELD-WIRE.MD) uses
EDP-Serialisation rather than a Logging-local codec. GCC/Clang and
fresh three-run real ESP32 WROOM qualification passed. These proofs
do **not** establish the complete Typed Envelope or persistent durability.


## Host historical G4 validation and temporal comparison

The Python host decoder validates Field11 as exactly the ordered pair
[ClockCorrelationProjectionStatus, TemporalQualityAssessment] and
Field14 exactly zero. Unknown enum values, wrong array shapes and
reserved facts fail closed. Cross-device ordering requires projection
Correlated and assessment Reliable at both sources plus same nonzero
ClockEra, eligible synchronization and finite uncertainty. Otherwise
Incomparable; no fabricated chronology. The CLI exposes owner numeric
values without asserting an authenticated producer.

## 12 November 2026 — complete canonical LogRecord validation result contract

**Exact source:** [`LogRecord.hpp`](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/8d2b307a8a1db1aa5596abc904cd0da1f3c032cd/src/logging/LogRecord.hpp). `LogRecordValidation : uint8_t` has ten independent outcomes: **Valid (0)** means the complete fixed 15-field record satisfies the declared source semantic constraints; **InvalidDevice (1)** means an unissued/zero strong System DeviceIdentifier; **InvalidIncarnation (2)** means a nonvalid System RuntimeIncarnationId; **InvalidAttempt (3)** means a zero/unissued per-incarnation AttemptSequence; **InvalidSequenceWidth (4)** means stored width does not match the `BasicLogRecord<TWidth,...>` template's exact 16/32/64-bit owner choice; **InvalidSyncEvidence (5)** means the synchronized coordinate, Clock state, Era and uncertainty facts disagree; **InvalidSeverity (6)** means emitted Severity is outside the permitted six values; **InvalidMessage (7)** means generated message's String component is reserved (<3), even though Domain/SubDomain numeric zeros may have owner-defined meanings; **InvalidTemporalProvenance (8)** means the EDP-Clock-issued Projection/Quality value pair exceeds the qualified source enum bounds; and **ReservedRecordFacts (9)** means a nonzero unassigned Field14 facts byte is being emitted before its owner defines that vocabulary. These exact values are not new wire tags.

`ValidateLogRecord<TWidth,TMaximumArguments,TArgumentBytes>(const BasicLogRecord<...>&)` is a pure constexpr validation with no provider calls, allocations or mutation. It checks permanent strong field identity, source Clock/Era coherence and reserved facts **before** downstream generated schema projection; success does **not** by itself validate Field13 generated argument types or persistence. `TWidth` selects the per-incarnation attempt width; `TMaximumArguments` and `TArgumentBytes` fix owned bounded argument storage, both contributing to the complete type's memory layout. The earlier page's description of Field11 synchronization quality is not a guarantee of actual cross-node precision.

`LogMessageIdentifier::From<TIdentifiers>(generatedIdentifier)` copies the **owner-issued EDP-Localisation** Domain/SubDomain/String strong values without truncation into three fixed 32-bit source-side components, not a synthetic identifier registry. `LogTemporalProvenance` stores the existing Clock `Projection` and `Quality` enum pair; `LogRecordFacts` stores the reserved `Value` byte, zero until issued. `BasicLogRecord` stores `Message`, `Level`, `Device`, `Incarnation`, `Attempt`, `SequenceWidth`, `Monotonic`, optional `Synchronized`, `SyncState`, `Era`, `Uncertainty`, `Provenance`, bounded source `Arguments`, generated diagnostic fingerprint and Facts under the canonical EDP-System SchemaType/FieldSet identity. It owns its argument bytes; it never borrows temporary producer values. The fixed `LogRecord` alias selects the normal default template shape, and the declared `Fields` FieldSet fixes all **15** permanent owner field numbers. Actual materialized wire goes through EDP-Serialisation, not a native C++ structure dump.
