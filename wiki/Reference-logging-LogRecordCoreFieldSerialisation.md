# LogRecordCoreFieldSerialisation — implementation reference

**Classification:** Internal cross-library scalar/enum adaptation. **Owning header:** [src/logging/LogRecordCoreFieldSerialisation.hpp](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/feature/logging-v1/src/logging/LogRecordCoreFieldSerialisation.hpp). **Version:** 0.1.0, source branch feature/logging-v1. ## Responsibility and boundaries

Defines the scalar and semantic representations and success-aware reverse conversions required for the canonical LogRecord core fields, including certified fixed-width enum domains and existing ClockEra adapters.

## Resource, failure and lifecycle invariants

Conversion statuses are strongly typed rather than Boolean. Reject unknown or reserved enum/provenance values; never hide failed reverse conversion or imply that a native C++ scalar layout equals CBOR.

## 12 November 2026 — complete strict core-field scalar owner mapping

**Exact source:** [`LogRecordCoreFieldSerialisation.hpp`](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/8d2b307a8a1db1aa5596abc904cd0da1f3c032cd/src/logging/LogRecordCoreFieldSerialisation.hpp). `LogRecordCoreFieldConversion : uint8_t` has **Succeeded (0)** — the issued source semantic value was faithfully converted to/from its unique canonical wire value; **InvalidSemanticValue (1)** — the source or candidate wire value violated the actual EDP-System/Clock/Logging owner predicate (e.g. reserved message String, invalid nonzero attempt, unsupported Severity enum or invalid Clock canonical value). Never coerce an invalid source into an arbitrary valid wire representation.

Private `Detail::LogRecordScalarRepresentation<TSemantic,TWire>` is an intentionally **unspecialized primary declaration**, preventing accidental conversion of arbitrary Types. Its explicit approved specializations cover `LogMessageIdentifier ↔ array<uint32_t,3>`, six `Severity ↔ uint8`, ticket-width-exact `AttemptSequence<TWidth> ↔ owner Storage`, canonical `Clock::MonotonicTimestamp ↔ uint64`, `Clock::SynchronizedTimestamp ↔ uint64`, `Clock::SynchronizationUncertainty ↔ uint32` and the other explicitly listed source strong/enum fields. Each specialization supplies precise static `To(source,wire)` and `From(wire,source)` conversion methods with strong `LogRecordCoreFieldConversion` result, validating source values before public output is set. These helpers are **INTERNAL owner contracts**, not an alternative schema registry.

`Serialisation::EnumSerialisationTraits<Severity>` and `<Clock::SynchronizationState>` bind the issued underlying uint8 width. The existing `Serialisation::CanonicalRepresentation` specializations map supported core LogRecord/Clock source types to their exact wire arrays/scalars; the matching `Bounded::TypeConversionAdapter` specializations expose typed `ResultType`, `IsAvailable`, `IsNoexcept`, `IsSuccessful` and typed bidirectional `Convert`, delegating to the internal approved `To/From` traits. Field13 positional arguments are **not** serialized here; they require a generated EDP-Localisation message signature and EDP-Serialisation positional adapter. The result is a fixed, source-validated canonical wire contract, not a C++ structure memory dump or an implicit persistent log.
