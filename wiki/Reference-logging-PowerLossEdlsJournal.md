# Reference — `src/logging/PowerLossEdlsJournal.hpp`

**Classification:** PUBLIC OPT-IN finite history wrapper around the existing `PowerLossEdlsSnapshots` archive owner and the application's independently PowerLoss-qualified EDP-Persistence **KeyValueStorage** provider. [Exact source](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/8d2b307a8a1db1aa5596abc904cd0da1f3c032cd/src/logging/PowerLossEdlsJournal.hpp). This is one N+1 **key/value generation** profile, not a second filesystem or default unbounded logging sink.

## Public value `DurableEdlsHistoryObservation`

`Status : DurableEdlsStatus` is the exact snapshot/physical-history classification and defaults to ProviderFailure; `OldestRetained : uint64_t` identifies the oldest generation still protected under the configured finite retention window; `Newest : uint64_t` identifies the newest committed generation, which may include a valid write that completed **after the application was interrupted but before it observed its acknowledgement**; `RetainedCount : size_t` is the number of individually verified complete EDLG frames retained. Each defaults to zero except Status. **Clean** and **Empty** allow further appends; **Degraded** can allow read-only recovery of independently verified protected history but *must not* allow mutation. Ambiguous/corrupt/provider-failure states fail closed.

## Public class template `PowerLossEdlsJournal<TSlots,TMaximumValueBytes,TMaximumFramePayloadBytes,TStorage>`

**`TSlots`** is the number of physical distinct KeyValueStorage keys, compile-time constrained to **2–8**, giving an exact finite retained capacity of **N=TSlots−1** records and one sacrificial key. **`TMaximumValueBytes`** is the bounded complete EDLS encoded key/value ceiling, no larger than the provider's qualified NVS value size (the tested profile uses at most 512 bytes). **`TMaximumFramePayloadBytes`** is the bounded complete EDLG framed payload profile; the combined EDLS/EDLG representation must fit the configured value. **`TStorage`** is the existing app-selected KeyValueStorage concrete with PowerLoss atomic key publication qualified separately; no unspecified storage provider acquires such a guarantee merely by satisfying the template.

The class has one private member **`snapshots_`**, a contained `PowerLossEdlsSnapshots<TSlots,TMaximumValueBytes,TMaximumFramePayloadBytes,TStorage>` that owns bounded key inspection, EDLG/EDLS encoding/checksums, exact native `StoreValue` and independent readback. This wrapper does **not** duplicate those persistence algorithms. The application owns the **lifetime** and exclusive synchronization of `TStorage` and the array of `TSlots` nonaliasing canonical `KeyView` names. The explicit constructor borrows the provider and key array, establishes that configured profile and does not itself append an entry.

## Public methods, lifecycle and failure behavior

`Inspect() const noexcept` calls the snapshot inspector **read-only**, propagates Empty directly, otherwise allows only Clean or Degraded physical evidence. For nonzero newest generation and a valid newest slot it computes `RetainedCount=min(Newest,TSlots−1)`, then `OldestRetained=Newest−RetainedCount+1`. For **each** retained age it demands a CRC-clean exact physical slot and matching generation in canonical modulo-`TSlots` order. When all physical keys are occupied, it additionally demands the next sacrificial slot's generation lies **outside** the protected retention window. Any gap, duplicate/misordered retained slot, noncanonical newest location or sacrificial overwrite risk produces Ambiguous and refuses to certify retained history. A full non-mutating scan is not proof of future electrical retention.

`Append(identity,incarnation,frame) noexcept` accepts an application-supplied exact 16-byte DeviceIdentifier, nonzero runtime incarnation and borrowed CRC-clean complete EDLG frame. It first performs `Inspect`; only Clean/Empty may mutate. It delegates a single new generation to the existing snapshot owner's `Commit` into its sacrificial key. A nominally committed native StoreValue is reported as **Committed only after independent exact readback** and a second history inspection confirms the expected next generation and canonical retained window. Otherwise it preserves a typed `DurableEdlsCommitOutcome<TSlots>` and returns failure/ReadbackUnconfirmed; it never falsely retires still-protected predecessor bytes. If power disappears after a native commit but before caller acknowledgement, a **later complete generation may legitimately appear on replay**; only committed generations outside the configured N most recent are eligible for retirement.

`RecoverRetained(generation,destination) const noexcept` first inspects the retained history, accepting Clean or read-only Degraded evidence. It rejects a requested generation outside the current `OldestRetained..Newest` window and returns `InvalidRecord` with zero offered bytes. In-range recovery delegates to the snapshot owner, which revalidates complete EDLS/EDLG CRC before copying into caller-owned bounded destination. A result does not authenticate the record or reconstruct any historical translated diagnostic text.

## Correct durability and retention scope

This profile assumes **atomic publication of an individual KeyValueStorage value** under the specifically tested concrete provider. It does **not** upgrade ordinary LittleFS/VFS FileStorage `ReplaceFile`, guarantee Flash wear/endurance, allocate storage at runtime, or promise indefinite historical retention. Physical RPI400 WROOM GPIO17 relay cuts qualified selected NVS retained-history generations (including a POR-classified run on 23 October); the exact electrical and protected-data witnesses are in [PowerLoss EDLS Journal](../docs/POWERLOSS-EDLS-JOURNAL.MD), [NVS fixture](../tests/hil/g7-nvs-journal-espidf/README.MD) and [G1–G15 acceptance](../docs/ACCEPTANCE-G1-G15.MD). This journal does **not** replace the newer strict-ACK LittleFS immutable-segment workload used by the full managed 100-records/sec Logging profile.
