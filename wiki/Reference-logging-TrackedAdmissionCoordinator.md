# Reference — `src/logging/TrackedAdmissionCoordinator.hpp`

**Classification:** PUBLIC OPT-IN bounded acquisition/lease/drain ownership API, plus PRIVATE lock-free counters, lifecycle guard and destructor notifier. [Source](../src/logging/TrackedAdmissionCoordinator.hpp). Importing it activates the sibling `AdmissionLifecycleCoordinator` and its abstract **EDP-Clock, Memory, Platform and Threading** owner contracts; the default Logging umbrella does not import it. No second worker, pool, clock, persistent lease registry or heap is introduced.

## Every public validation and drain result value

`TrackedAdmissionValidation : uint8_t`: **Valid (0)** — the supplied guard is owned by this coordinator and empty, so admission was actually attempted; **WrongCoordinator (1)** — the guard belongs to another coordinator, no Memory call occurs; **LeaseOccupied (2)** — guard already owns/contains a lease, so no overwrite or Memory call occurs.

`TrackedAdmissionResult` contains **Validation** (the above structural outcome) and **Admission : CoordinatedAdmissionResult** (the existing lifecycle owner's actual typed admission/late-grant/shutdown and wake-publication result). A Valid result may still carry any truthful capacity/provider/deadline result; validation alone is not a successful allocation.

`TrackedDrainStatus : uint8_t`: **Quiescent (0)** — exactly zero active outer admissions, no lifecycle admissions and no remaining tracked leases; **DeadlineElapsed (1)** — canonical absolute monotonic deadline passed before safe quiescence; **WakeRetryLimitReached (2)** — finite drain wake budget exhausted while work still existed; **DrainWaitProviderFailure (3)** — Threading bounded WaitUntil owner failed rather than timing out; **UnconfirmedNativeRelease (4)** — a native lease destructor/release may have freed capacity but exact success cannot be observed, **so quiescence must not be asserted**.

`TrackedDrainResult` value members are **Status** (one of these five), **WakePublication : AdmissionWakePublicationResult** (actual request-shutdown wake outcome), **ActiveAcquisitions : uint32_t** (observed active outer calls), **OutstandingLeases : uint32_t** (granted but not affirmatively released tracked leases), **UnconfirmedReleases : uint32_t** (sticky count of unproven native releases), **WakeFailures : uint32_t** (failed advisory producer/drain wake publication attempts). The drain result samples each atomic separately. The fields can therefore describe different instants when producers or lease owners are still active. Bootstrap joins application tasks separately.

## Public `TrackedAdmissionCoordinator<TProducerCount,TWaitWakeProvider>`

**Template parameter `TProducerCount`** is the exact positive compile-time number of registered producer wake slots. **`TWaitWakeProvider`** is the existing Bootstrap-owned Threading wait/wake concrete, whose declared `Capacity` must exceed `TProducerCount` to reserve one additional stable shutdown-drain slot. The implementation requires always-lock-free `std::atomic<uint32_t>` at compile time; it does not assume 64-bit atomics are lock-free on ESP32. These constraints define persistent RAM/capacity at Bootstrap, not unbounded dynamic registration.

**Private state and ownership:** `_waitWake : TWaitWakeProvider*` borrows the stable external wake owner and must outlive every operation and guard; `_lifecycle : AdmissionLifecycleCoordinator<TProducerCount,TWaitWakeProvider>` is the sole embedded cancellation/deadline/wake coordinator. `_inflight : atomic<uint32_t>` counts active **outer** coordinator acquisition calls, including the critical interval after nested admission returned but before a newly granted lease is included in outstanding count; `_outstanding : atomic<uint32_t>` counts only successfully granted leases still owned via the tracked guard; `_unconfirmedReleases : atomic<uint32_t>` is sticky uncertainty when RAII destruction cannot positively determine native Memory release; `_wakeFailures : atomic<uint32_t>` records failed advisory notifications. `DrainSlot = TProducerCount` is the exact extra non-producer wake slot reserved for orderly shutdown. These counters must not be decremented merely because an unobservable destructor may have succeeded.

**Private helpers:** `WakeDrain()` wakes the drain slot only after shutdown has been requested and counts notification failures without pretending it became quiescent. `WakeAfterNativeLeaseDestruction()` issues best-effort wakes to all producer slots and the drain slot **after** native RAII destruction, still preserving unconfirmed release accounting. `InflightScope` retains a backpointer to its exact coordinator; its destructor decrements `_inflight` and notifies drain *after* the outer acquisition leaves. This prevents a false zero count in the admission→tracked-lease handover window.

The explicit constructor borrows the Threading provider and constructs its embedded lifecycle coordinator; it neither starts a Task nor owns the actual wake provider. Copying and moving the coordinator are deleted to keep all outstanding guard pointers and wake indices stable.

## Nested public `TrackedLease<TLease>` — the only tracked native lease owner

**Template parameter `TLease`** must be default constructible and provide noexcept `Release()` and const `IsEmpty()`. A `TrackedLease` is noncopyable and nonmovable; its constructor takes its specific coordinator reference. Private **`_lease : TLease`** is the actual existing EDP-Memory move-only lease and **never** exposed for manual transfer; **`_owner`** identifies the exact coordinator; **`_tracked`** is the authoritative “grant not yet positively released” Boolean. **`_postNative : NativeDestructorNotifier`**, intentionally declared **before** `_lease`, therefore destroys **after** the native lease (reverse member destruction order), allowing one last best-effort notification after that native destructor's unobservable retry. The guard must finish destruction while its coordinator and the borrowed wait/wake provider remain alive.

Nested `NativeDestructorNotifier` contains private **Owner** pointer and **MayHaveReleasedCapacity** flag. Its destructor wakes producers and the drain slot only when the owning TrackedLease destructor observed a native release failure and the native lease destructor subsequently *might* have freed capacity; it never treats that possible success as confirmed.

`IsEmpty() const` queries the underlying native lease without mutating ownership. `Get()` / `Get() const` borrow the current object and are valid only while the lease remains live; no new pointer lifetime guarantee is introduced. `Release()` performs the lifecycle coordinator's existing native `ReleaseAndNotify`; on **ReleasedAndNotified** or **ReleasedNotificationFailed**, it clears `_tracked`, decrements outstanding exactly once, counts any failed advisory wake, and wakes the drain slot. A native `MemoryProviderFailure` does *not* clear tracking. The guard destructor attempts this release if still tracked; if the provider reports failure, it increments sticky `_unconfirmedReleases`, permits the native lease's own destructor to attempt its final release, then uses the post-native notifier to wake consumers **without manufacturing a successful ownership release**. No direct raw lease escape, copying or move across coordinators is allowed.

## Acquisition and shutdown methods

`AcquireUntil<TMaximumWakeRetries,TObjectPool,TLease,TArguments...>(slot,pool,guardedLease,deadline,arguments...)` takes one finite compile-time wake/retry limit, an application-owned Memory pool (borrowed), this coordinator's exact empty TrackedLease, an EDP-Clock canonical absolute monotonic deadline and forwarded object constructor arguments. It rejects wrong owner or occupied output **before** entering Memory. It increments the outer `_inflight` before invoking the existing cancellation-aware lifecycle `AcquireUntil`, whose underlying Memory capacity claims use **NoWait**, not unsafe native blocked finite/Forever acquisition. On **Admitted**, **GrantedAfterDeadline** or **GrantedDuringShutdown**, it increments `_outstanding` and marks the guard tracked **before** the outer InflightScope leaves, preventing shutdown from reporting a false clean gap. The caller must explicitly release even a late/shutdown grant; a deadline or stop does not magically cancel a successful native Memory claim.

`RequestShutdown()` delegates to the existing lifecycle's terminal shutdown publication and returns its honest `AdmissionWakePublicationResult`. `OutstandingLeases() const` and `UnconfirmedReleases() const` are acquire-ordered read-only observations, not additional state owners.

`ShutdownTrackedUntil<TMaximumDrainWakes>(deadline)` is for **one** application-owned drain caller and requires a strictly positive maximum wake count. It first requests shutdown, then checks sticky release uncertainty **before** clean-quiescence acceptance. A clean result requires zero outer `_inflight`, zero `_outstanding`, and zero embedded lifecycle active admissions; otherwise it waits on the **existing Threading drain slot** via `WaitUntil(DrainSlot, deadline)` until quiescence, canonical deadline, provider failure or exhaustion. Each return includes all counters and the actual shutdown-wake publication result. It does **not** join Tasks, settle sinks, release untracked raw leases or guarantee bounded underlying provider latency beyond their separate contracts.

## Resource/failure boundary and validation

The owner accounts **only** for grants issued through this coordinator. Raw Memory leases previously created elsewhere are **not retroactively tracked**, and a clean tracked drain does not permit tearing down a shared pool if other owners still hold leases or pending Tasks. The caller/Bootstrap must stop new producers, join all tasks, flush/settle sinks and validate every separately owned provider. This path deliberately avoids EDP-Memory's unresolved direct native finite/Forever blocked-waiter failure issue ([Memory #16](https://github.com/ESPressio-Development-Platform/EDP-Memory/issues/16)).

GCC/Clang owner tests include wrong guard, extra producer count, capacity saturation, RAII destructor, wake failure, shutdown racing a grant, and unconfirmed native release. The larger managed WROOM/EDLS strict-NVS-ACK profiles have separately recorded bounded evidence; those do not certify every provider's runtime or global application lifetime.
