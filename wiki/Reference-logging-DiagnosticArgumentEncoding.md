# Logging DiagnosticArgumentEncoding — bounded governed arguments

**Opt-in public G3 extension**, version `0.1.0`. `logging/DiagnosticArgumentEncoding.hpp` consumes actual **EDP-Localisation generated** `DiagnosticMessageSchema`, **EDP-Serialisation** canonical positional CBOR/JSON and **EDP-BoundedTypes** values.

`IsDiagnosticSchemaMatching<Schema,ActualTypes...>()` returns true when the generated message is declared and its positional kinds match. Supported values: bool, exact-width signed/unsigned integer and float/double, compile-time `Bounded::String<N,Provider>` for `Utf8`, `Bounded::Bytes<N,Provider>` for `Bytes`, owner-certified `System::TypeIdentifier`, `System::FieldIdentifier`, `System::Identity::DeviceIdentifier`, `System::Identity::RuntimeIncarnationId`, and the explicitly imported EDP-Clock `ClockEra` adapter. `EncodeDiagnosticArgumentsCbor/Json` enforce the same generated contracts and require actual EDP-Serialisation `SerialisableType`, returning typed results and preflight buffer correctness.

**No guessed conversions** for unsupported Localisation StringIdentifier or bespoke enums. Exact owner-certified **DeviceIdentifier**, **RuntimeIncarnationId**, and opt-in **ClockEra** are supported; their governed generated parameter kinds must match exactly, and their serialisation still belongs to EDP-Serialisation. No governed G4 LogRecord root TypeIdentifier, typed envelope, archive, transport or durability is created by this adapter. See [G3 bounded arguments](../docs/DIAGNOSTIC-BOUNDED-ARGUMENTS.MD), [Dependencies](../DEPENDENCY_GRAPH.MD).

## Exact generated strong owner types (2026-10-22)

The generated signature now accepts `RuntimeIncarnationId` and explicitly certified ClockEra without casting either to primitive integer call-site arguments. `EncodeDiagnosticArgumentsCbor` and `EncodeDiagnosticArgumentsJson` delegate to EDP-Serialisation, enforcing the generated Localisation argument-kind list at compile time. Source capture uses a separate bounded native arena whose descriptors must never be treated as wire tag numbers. Real owner-generated fixtures with both strong values, golden CBOR/JSON positionals and GCC/Clang negative type mismatch tests pass. This helper itself encodes Field13 **only**; the separately implemented `GeneratedLogRecordWireProjection` and typed EDLS Task adapters cover the full 15-field LogRecord in their independently qualified source/target profiles.

## Source-owned values to canonical writer

The optional `OwnedDiagnosticPositionalReencoding.hpp` bridges fixed source-native descriptors to this module's generated-message-qualified `EncodeDiagnosticArgumentsCbor/Json` APIs. The caller provides a bounded scratch tuple of exact semantic Types; private `OwnedArgumentKind` numbers are not CBOR tags. Owner string, bytes and strong identity constraints remain active, and first-refusal results preserve typed reasons. See [Owned positional re-encoding reference](Reference-logging-OwnedDiagnosticPositionalReencoding.md).

## 12 November 2026 — internal trait, predicate and precise template contract

**Source:** [`DiagnosticArgumentEncoding.hpp`](../src/logging/DiagnosticArgumentEncoding.hpp). **INTERNAL** `Detail::IsBoundedDiagnosticString<TValue>` and `Detail::IsBoundedDiagnosticBytes<TValue>` default to false and specialize to true only for existing EDP-BoundedTypes `String<TCapacity,TByteOperations>` or `Bytes<TCapacity,TByteOperations>`; `TValue` is the exact original C++ value Type, `TCapacity` the finite owner-selected byte bound and `TByteOperations` the existing copy-provider Type. `Detail::IsCertifiedDiagnosticClockEra<TValue>` defaults false and becomes an exact owner-issued strong ClockEra match **only** if the optional `DiagnosticClockEraArguments.hpp` specialization is imported. None creates a separate runtime registry, Heap allocation, logging state, or CBOR tag assignment.

**INTERNAL** `Detail::DiagnosticArgumentKindFor<TKind,TValue>() consteval` maps an exact supported C++ Type `TValue` to **`TKind`**, the generated EDP-Localisation descriptor's **own** argument-kind enum (Boolean, signed/unsigned fixed widths, Float32/Float64, Utf8, Bytes, strong System identities, optional ClockEra). Unsupported/unissued Types fail at compile time. `TKind` is supplied by the generated owner; Logging does **not** define a competing argument-kind enum.

**PUBLIC** `IsDiagnosticSchemaMatching<TGeneratedMessageSchema,TValues...>() consteval` reads generated `Declared`, `ArgumentCount` and `ArgumentKinds`, verifies that generated ordered kind array equals the Types in `TValues...` exactly, and returns a compile-time Boolean. `TGeneratedMessageSchema` must be the generated EDP-Localisation descriptor, `TValues...` the exact argument Types.

**PUBLIC** `EncodeDiagnosticArgumentsCbor<TGeneratedMessageSchema,TValues...>(destination,values...)` and `EncodeDiagnosticArgumentsJson<...>` require a matching generated Type list and each EDP-Serialisation `SerialisableType<TValues>` by compile-time assertion. `destination` is caller-owned bounded output, `values...` are borrowed exact C++ argument references; both functions return the existing strongly typed `ESPressio::Serialisation::SerialisationResult` and delegate to `SerialisePositionalCbor<ArgumentCount>` or `SerialisePositionalJson<ArgumentCount>`. They do not invent a second codec or automatically serialize a LogRecord envelope, capture native argument bytes beyond the call, allocate a new provider, choose Clock synchronization, or persist an EDLS generation. Caller must handle partial/rejected output according to the owner result; a valid generated schema is necessary, not a durability ACK.
