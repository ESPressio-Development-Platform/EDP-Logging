# EdlsPowerLossAcknowledgement — implementation reference

**Classification:** Public optional durable-protocol owner. **Owning header:** [src/logging/EdlsPowerLossAcknowledgement.hpp](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/feature/logging-v1/src/logging/EdlsPowerLossAcknowledgement.hpp). **Version:** 0.1.0, source branch feature/logging-v1. This page describes implementation and owner requirements; it does not replace normative ./docs contracts.

## Responsibility and boundaries

Coordinates immutable EDLS candidate publication with independent NVS KeyValueStorage acknowledgement and protected predecessor readback. A candidate is not durable until the exact acknowledged generation and contents have been separately committed and validated.

## Resource, failure and lifecycle invariants

Generic FileStorage remains weak under interruption; the application must supply a separately PowerLoss-qualified NVS key provider and a finite approved immutable segment topology. Never retire a protected predecessor before the successor and acknowledgement are independently confirmed.
