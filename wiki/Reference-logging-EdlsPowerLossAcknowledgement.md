# Source reference — PowerLossAcknowledgedEdls

**Classification:** PUBLIC OPTIONAL strict two-provider EDLS durable-publishing contract, with PRIVATE exclusive-writer optimisation. **Exact reviewed source:** [src/logging/EdlsPowerLossAcknowledgement.hpp](https://github.com/ESPressio-Development-Platform/EDP-Logging/blob/8d2b307a8a1db1aa5596abc904cd0da1f3c032cd/src/logging/EdlsPowerLossAcknowledgement.hpp). EDP-Logging 0.1.0. The source directly consumes **EDP-Persistence's existing FileStorage and KeyValueStorage** abstractions and Logging's EDLS rolling/seal/inspection helpers; it neither supplies a filesystem nor assumes every FileStorage is power-loss atomic.

## Essential contract and exact status values

An accepted, durable EDLS **generation** means (1) the entire immutable successor is independently CRC-inspected on its physical FileStorage path, **and** (2) an *independent KeyValueStorage provider that specifically advertises PowerLoss retention and interruption atomicity* has durably committed and returned a checked readback of an EDLS-format ACK watermark. A FileStorage `ReplaceFile` success or a clean post-write readback alone **does not** grant a durable ACK. The protected history retains the latest `TProtectedSlots` generations with `TPhysicalSlots = TProtectedSlots + 1` physical slots; the extra slot is the sacrificial successor. Retire an eligible predecessor only *after* ACK is confirmed, never before.

`EdlsAcknowledgedStatus : uint8_t` exhaustively distinguishes:

- **Ready (0):** an existing exact watermark was read and validated; not a new publication.
- **Initialized (1):** the archive was proven physically empty and a new genesis ACK=0 was stored and read back; no legacy history was adopted.
- **MissingWatermark (2):** no KeyValueStorage ACK exists; no assumption about ungoverned existing FileStorage contents.
- **InvalidWatermark (3):** watermark framing, identity, incarnation, length, CRC or reread facts conflict with the required EDLS-format ACK contract.
- **ArchiveAmbiguous (4):** physical paths, retained generation continuity or candidate provenance cannot be reconciled safely; no destructive recovery.
- **AcknowledgedHistoryChanged (5):** a protected predecessor could not be reverified or its header identity, verified frame count or CRC-qualified prefix length changed. The operation fails closed.
- **UnacknowledgedCandidateRemoved (6):** independent ACK proves a non-protected candidate was removed by recovery; the acknowledged window remains intact.
- **CommittedOldestRetired (7):** recovery completed retirement of an *already ACKed* successor's oldest eligible prior generation.
- **NoPhysicalReserve (8):** the immutable protected archive has no safely absent successor path; cannot overwrite a protected record.
- **GenerationExhausted (9):** nonwrapping 64-bit generation/ACK representation cannot advance.
- **ProviderFailure (10):** actual FileStorage/KeyValueStorage operation/readback could not satisfy its required native contract.
- **WatermarkStoreRejected (11):** independent KeyValueStorage StoreValue or its exact readback/identity check failed; never report publication as ACKed.
- **PublishedNotAcknowledged (12):** a successor may be present but was not proven safe/complete and durably acknowledged; recovery must reconcile its candidate.
- **AcknowledgedWithinCapacity (13):** successor and separate ACK verified while fewer than the protected generation capacity were previously held.
- **AcknowledgedAndRetired (14):** successor and separate ACK verified, then eligible old protected predecessor was successfully retired.
- **AcknowledgedPendingRetirement (15):** successor **already durably ACKed** but physical cleanup of an old eligible predecessor could not finish; this is *not* a failed ACK and must be reconciled before further mutation.
- **InvalidByteCapacity (16):** immutable application-selected logical byte budget cannot reserve a minimal valid framed segment plus all physical slots and the ACK value.
- **ByteCapacityExceeded (17):** incoming complete segment or already present file exceeds its explicitly reserved per-slot logical byte share; no silent enlargement.

`EdlsAcknowledgedObservation` contains **Status** (default InvalidWatermark), **AcknowledgedGeneration** (last NVS-certified segment generation, zero before genesis/when unknown), **CandidateSlot** (physical location implicated in publication/recovery, or `TPhysicalSlots` sentinel for none), and **AcknowledgedIncarnation** (the runtime incarnation stored for the *last ACKed* generation, not necessarily this boot). Never read the generation or slot fields as a new ACK unless Status actually certifies it. Acknowledged generation names a **segment**, which may contain multiple records.

## Template declaration, owner constraints and retained state

`PowerLossAcknowledgedEdls<TPhysicalSlots,TProtectedSlots,TPayloadMaximum,TSegmentMaximum,TFileStorage,TKeyValueStorage>` is a single **non-allocating application Bootstrap-composed** archive owner. `TPhysicalSlots` is the exact immutable bounded FileStorage path count (maximum 64); `TProtectedSlots` is the retained number of verified predecessor segments (minimum 2), constrained to `TPhysicalSlots-1`; `TPayloadMaximum` is a positive bounded maximum individual EDLG payload (1–4096); `TSegmentMaximum` is the complete EDLS physical segment ceiling, at least header + maximum payload + frame overhead. `TFileStorage` must implement the established mandatory FileStorage operations; **`TKeyValueStorage`** must be a qualifying EDP-Persistence composition provider advertising `RetentionLevel::PowerLoss`, `InterruptionAtomicity::PowerLoss`, `AccessMode::ReadWrite`, and sufficient exact value size for the 40-byte watermark. These compile-time property checks prevent the strict ACK class from silently treating a generic VFS FileStorage as a power-atomic ledger. No hidden Flash selection or secondary persistence owner exists.

The class's private retained fields are all semantically relevant:

- **`byteCapacity_`** is the **const** application-chosen logical byte reservation, including 40-byte ACK value and every physical slot's equal share; it is fixed at construction/Bootstrap and cannot be grown after initialization. Filesystem block metadata and physical allocation overhead remain a separate application responsibility.
- **`files_`** borrows the exclusive existing FileStorage provider; **`watermark_`** borrows the independently PowerLoss-qualified KeyValueStorage provider. Neither provider is constructed or owned here; both must survive every in-flight scan/publication/retirement.
- **`paths_`** stores the bounded application-issued array of canonical FilePathView physical locations; every identity must be unique, point to the chosen concrete and remain valid while the archive lives. **`watermarkKey_`** stores the distinct KeyView for the independently committed watermark.
- **`identity_`** captures the expected nonzero 16-byte DeviceIdentifier to prevent mixing unrelated archives; **`incarnation_`** captures the current application-issued nonzero runtime incarnation. The NVS ACK can refer to a *previous boot's* incarnation; recovered retained history may legitimately span boots.
- **`exclusiveWriterCompleted_`** is a volatile, derived optimisation hint, never a durability fact. It is true *only after this same exclusive writer completed a full predecessor/successor proof, separate NVS commit/readback and required retirement*, and must be invalidated after boot, explicit Recover or **any uncertain publication**. **`exclusiveWriterAck_`** is the corresponding remembered ACK generation for *that* fully verified exclusive-writer transaction, checked against a fresh independent watermark read before reuse. Neither field substitutes for a new physical full CRC-clean preflight or is safe under external concurrent writers.
- **`Capability`** and **`Properties`** are internal aliases selecting the existing EDP-Persistence KeyValueStorage Composition capability and inspecting its certified provider properties. They do not create another property system.

## Internal helpers and failure-preserving operations

**`SegmentByteCapacity() const`** derives the per-slot budget as `min(TSegmentMaximum, floor((byteCapacity_-EdlsHeaderBytes)/TPhysicalSlots))` with zero on underflow. Equal shares reserve room for one immutable successor even if the preceding record batches had varying byte sizes; the extra ACK value is accounted for separately. **`IsByteCapacityValid() const`** requires at least an EDLS header plus a minimally nonempty 21-byte EDLG frame in each slot. Both are read-only, no dynamic allocation.

**`StoreWatermark(latest)`** is the internal sole ACK mutation: it refuses generation wrapping or invalid current incarnation, encodes a canonical 40-byte EDLS v1 header (`Slot=0`, `Generation=latest+1`, expected identity and current incarnation), calls the existing KeyValueStorage `StoreValue` **once**, then **independently calls `Read()`** and verifies generation/incarnation/identity. A store that fails or cannot be verified returns WatermarkStoreRejected; it must **not** be reported as accepted durable history.

**`PublishFrameSequence<TMaximumFrames>(completeEdlg,scratch)`** is the private shared publisher used by both public single-frame and batch APIs. `TMaximumFrames` is an explicit compile-time bound (up to 64; frames individually CRC-checked by existing successor/EDLG helpers), and all input/scratch spans are caller-owned, disjoint, and valid for the synchronous transaction. It rejects inadequate immutable budget before mutation; performs a full explicit `Recover` after uncertainty, boot or prior failure, or only on the fully verified same-exclusive-writer path checks a fresh `Read()` against `exclusiveWriterAck_`; scans and validates all existing protected predecessors, ensures physically absent spare, forbids generation wrap, publishes one CRC-verified immutable successor to that spare, rechecks predecessor header identity, frame CRCs, verified frame count and prefix length, **only then** writes/reads back the NVS watermark, and **only then** may retire the oldest eligible prior generation. A rejected watermark leaves the prior acknowledged window protected. If retirement fails after ACK, returns AcknowledgedPendingRetirement and requires recovery before the next publish. In either case the fast-path hint is invalidated unless the entire qualified transaction completed.

## Public constructor, readers, recovery and publishing

The explicit constructor borrows `files`, `watermark`, unique `paths`, a stable `watermarkKey`, nonzero `identity` and `runtimeIncarnation`, plus an optional **immutable** `byteCapacity` (defaults to ACK+all physical slots at the static TSegmentMaximum). It does not format a filesystem, adopt preexisting history or commit an ACK itself.

**`Read() const`** validates capacity, readiness of both providers and watermark key, reads *exactly* 40 bytes with independently reported size facts, parses the actual CRC header, checks Unsealed profile, Slot=0 and expected identity, and returns Ready with decoded Generation−1 and the *stored last-ACKed incarnation*. It never modifies files or treats a physical segment as a substitute for the separate ACK.

**`InitializeEmpty()`** is allowed only when Read reports MissingWatermark **and every physical FileStorage path is confirmed NotFound**; any existing, partial or unknown file makes initialization ArchiveAmbiguous. It then calls StoreWatermark(0), independently checks success, and returns Initialized with ACK zero. Booting with old ungoverned EDLS files is not grounds for silently assigning them a modern strict watermark.

**`Recover(scratch)`** invalidates the exclusive-writer hint, reads exact independent ACK, computes the newest bounded acknowledged generation range, visits every physical slot and separately verifies the complete EDLS/EDLG body CRC/identity/generation/path and per-slot byte limit. It rejects gaps, duplicates, unknown candidates, identity/incarnation mismatch and any missing still-ACKed predecessor. At most **one** unacknowledged candidate can be considered for removal or old eligible predecessor retirement; before and after that operation it re-verifies each protected predecessor and re-reads the unchanged NVS ACK. Corrupted, unsafely mutated or unprovable candidates **fail closed**, never sacrificing already ACKed generations.

**`ByteCapacity() const`** returns the immutable logical budget; **`ConfiguredSegmentByteCapacity() const`** returns the derived per-slot equal reservation, including EDLS header/seal when checking a batch; **`MaximumFramePayloadBytes()`** and **`MaximumSegmentBytes()`** expose compile-time limits to cooperating bounded batch/worker templates. **`Publish(completeEdlg,scratch)`** delegates to the one-frame `PublishFrameSequence<1>` path; **`PublishBatch<TMaximumFrames>(completeFrames,scratch)`** delegates to the same bounded algorithm for an explicit finite sequence, with **one** durable segment acknowledgement shared by all included records. These methods are not thread-safe under concurrent mutation: **Bootstrap must serialize entire writer, readback, physical scan and NVS update**, and must separately budget provider latency and task stack.

## Tests, power-loss scope and limitations

Strict host owner integration exercises negative NVS commits/readback, corrupted predecessors, interrupted candidates, ACKed-pending retirement, multi-record sealed segments, byte-capacity guard and cross-incarnation recovery. The named RPI400 WROOM-32 LittleFS+NVS managed-worker electrical relay profiles validate power-cut outcomes **only for the selected concrete fixtures and cut intervals**; see [acknowledgement and recovery](../docs/EDLS-ACKNOWLEDGED-RECOVERY.MD), [protected rolling](../docs/EDLS-PROTECTED-ROLLING.MD), [immutable byte capacity](../docs/IMMUTABLE-PERSISTENCE-BYTE-CAPACITY.MD) and [G1–G15 evidence](../docs/ACCEPTANCE-G1-G15.MD). Logical byte budgeting is not a physical wear model; no two-year lifespan, generic VFS interruption atomicity or indefinite retention is promised. Application-selected external Flash is preferable for heavy production logging.
