# Logging Python tooling — source-specific developer reference

**Classification:** INTERNAL TOOLING with public host CLI entry points. **Source root:** [tools/edp_logging/](https://github.com/ESPressio-Development-Platform/EDP-Logging/tree/8d2b307a8a1db1aa5596abc904cd0da1f3c032cd/tools/edp_logging). Current repository-local source reference, package 0.1.0. These 12 Python modules are standard-library, offline, **host-side** forensic/diagnostic readers and presentation tools, not ESP32 firmware, native persistence providers, a durable transport layer or an independent Logging ABI. The authoritative on-device framing/typed record contracts live in C++ and the EDP-Serialisation/Localisation/Clock/System owners. Python may validate what bytes it is actually given; it cannot prove which records an interrupted Flash write made durable.

For user-facing commands and parameters see [Tools and CLI](Tools-edp-logging), [Host decoder](Host-Decoder), [historical diagnostic source](Tooling-edp-logging-historical-diagnostic), and [forensic CSV](../docs/FORENSIC-CSV-EXPORT.MD). The per-module sections below document actual current source entry points, Type/field roles, limits and errors; they are not a mechanically generated list.

## 1. `__init__.py` — public package export contract

[Source](../tools/edp_logging/__init__.py). The package exports the maintained, selected C++ wire-equivalent reader vocabulary from its owners: `Frame`, `FrameIssue`, `FrameCodec`, `FrameStatus`, `crc32c`, `encode_frame`, `scan_stream` from framing; `SegmentHeader`, `parse_segment_header`, `encode_segment_header` from the EDLS wire module; `ArchiveInspection`, `SlotInspection`, `SlotState`, `inspect_slot`, `inspect_archive_slots` from conservative recovery; `EnvelopeError`, `PreservedFloat`, `TypedEnvelope`, `inspect_typed_envelope` from typed record structure; schema and record-fact readers plus attempt/time evidence from their respective modules. **This is an import/discovery surface, not a runtime registry**: importing the package must not mutate a filesystem, select a hardware provider, create a persistent history, or reinterpret corrupt bytes as valid records. Importers should handle each source module's typed exception and finite size bound rather than treating a successful `import` as evidence of an archive.

## 2. `__main__.py` — command entry

[Source](../tools/edp_logging/__main__.py). This intentionally minimal executable entry imports the existing `cli.main` and exits with its returned process status via `SystemExit(main())`. There is no second command parser or state owner; all error messages, input bounds, CLI flags and exit-code semantics remain in `cli.py`. Executed with `python -m edp_logging` after setting the expected tools package path. It neither loads any device/provider nor checks a physical ACK by itself.

## 3. `framing.py` — bounded EDLG v1 transport frame ownership

[Source](../tools/edp_logging/framing.py). This module is the portable host-side equivalent of the C++ `EdlgFrame` and `EdlgFrameReader` wire contract. Constants `MAGIC` and `COMPLETION` identify exact EDLG head/trailer; `FRAME_VERSION=1`, `HEADER_SIZE=16`, `OVERHEAD=20`, `DEFAULT_MAX_PAYLOAD=65536` and `DEFAULT_RESYNC_LIMIT=1048576` define finite parsing defaults, **not** permission for arbitrarily large ESP32 producer buffers. `FrameCodec` is the issued frame codec classification (CBOR or JSON); `FrameStatus` distinguishes valid data and transport damage/recovery classifications; frozen `Frame` contains the validated decoded frame evidence; frozen `FrameIssue` records a failed candidate/offset without inventing a log record. `crc32c(data,initial=0)` computes the same accidental-corruption CRC used by the native wire contract; it is not authentication. `encode_frame(codec,payload,max_payload)` validates codec and finite payload, emitting exactly one length+CRC-protected frame or raising `ValueError`. Private `_candidate_problem` validates bounded candidate headers. `scan_stream(stream,...)` scans a supplied file-like byte source with bounded resynchronisation and frames/issues, rejecting overlong or malformed frames without unbounded allocation or an invented recovery/retention policy. **Only complete verified frames** are source candidates for further typed parsing; a valid CRC does not establish semantic TypedEnvelope validity or durability.

## 4. `archive.py` — EDLS v1 header and sealed segment validation

[Source](../tools/edp_logging/archive.py). `SEGMENT_HEADER_SIZE=40`, `SEGMENT_MAGIC=b'EDLS'`, and `SEGMENT_VERSION=1` are the exact on-wire format; an EDLS segment contains an independently verified 16-byte source identity, nonzero 64-bit generation, physical 16-bit slot and nonzero 32-bit incarnation. `SegmentHeaderError` is the named invalid/malformed archive header exception. Frozen `SegmentHeader` exposes **slot**, **generation**, **device_identifier**, **incarnation**, and **profile** (0 Unsealed or 1 SealedFrames), all value facts, with no file handle or persistent owner. `parse_segment_header(data)` checks exact length, magic, version/profile, CRC32C and nonzero identities and returns that value only if complete. `encode_segment_header(header)` performs the reverse strict bounds/type checks, writing the C++-equivalent forty bytes for golden fixtures; it does **not** allocate a new generation or commit storage. `parse_sealed_segment(...)` validates EDLC completion/record count/length and whole-segment CRC, then the existing EDLG frame parser; **a valid prefix of a torn sealed segment is not silently promoted** to a durable complete batch. The module does not mutate FileStorage, interpret NVS watermark, or certify write atomicity.

## 5. `archive_recovery.py` — read-only bounded physical-slot forensics

[Source](../tools/edp_logging/archive_recovery.py). `SlotState` is a finite source-inspection classification, deliberately distinguishing empty, clean and unusable/ambiguous physical content. Frozen `SlotInspection` holds the checked facts of **one** addressed physical file (verified prefix/frames, header/condition and error details); frozen `ArchiveInspection` holds a bounded cross-slot summary and only the conclusions the observed files justify. `inspect_slot(...)` combines the exact EDLS header parser, EDLG scanner and optional sealed-segment inspector for one supplied byte source. `inspect_archive_slots(...)` examines the given fixed slot set conservatively for identity, generation, completeness and ambiguity, without writing anything. They never create or delete a physical path, choose a successor generation on disk, append behind a corrupt tail, acknowledge NVS or promote unconfirmed history. The current C++ strict EDLS writer resides in `src/logging/EdlsPowerLossAcknowledgement.hpp`. The Python module remains *intentionally* **read-only** even though production write/acknowledgement now exists elsewhere.

## 6. `record_structure.py` — strict EDP TypedEnvelope structural parsing

[Source](../tools/edp_logging/record_structure.py). `EnvelopeError` classifies malformed/unsupported canonical TypedEnvelope structure. Frozen `PreservedFloat` retains exact floating-point representation rather than coercing NaN/payload to an arbitrary Python number; frozen `TypedEnvelope` retains the structural root TypeIdentifier and field-value shape without fabricating generated message semantics. Private `_CborReader` validates finite CBOR structures; `_unique_object` rejects duplicate JSON keys, `_reject_nonfinite` rejects non-finite JSON constants, and `_validate_json` enforces recursion/budget and value-shape constraints. `inspect_typed_envelope(...)` is the public entry point for exact typed-envelope structure in a bounded EDLG CBOR/JSON payload; it cannot assume a particular historical diagnostic schema, translation language, System device identity or completeness of an outer archive. No indefinite container, arbitrary CBOR tag or automatic Unicode/float reinterpretation is introduced.

## 7. `record_facts.py` — issued permanent LogRecord field semantics

[Source](../tools/edp_logging/record_facts.py). `RecordFactError` represents an issued 15-field LogRecord structure or semantic validation failure; frozen `RecordFacts` captures verified permanent field evidence including source identity, local Monotonic and optional synchronized status/uncertainty/era, governed message/attempt and schema fingerprint as available. Private `_unsigned(value,maximum,label,minimum)` rejects out-of-range/native-signed coercions and includes a logical field label in its error. `inspect_log_record_facts(typed_envelope,...)` validates the exact approved root field map and owner-issued constraints; it does not extend Field14 flags, infer an unknown Root TypeIdentifier, translate historical strings, or assert a real synchronization source existed. A structurally valid value is evidence **about a candidate recorded source event**, not proof of provenance authenticity or Flash persistence.

## 8. `schema.py` — strict generated Localisation schema identity and typed arguments

[Source](../tools/edp_logging/schema.py). `KINDS` defines the supported finite set of approved generated parameter kinds (bool, exact signed/unsigned widths, float32/64, UTF-8, bytes and named strong System/Clock identifiers); it is **not** a runtime wire-tag registry. `SchemaError` is the named malformed/unsupported/provenance-mismatch failure. Frozen `Parameter` holds generated parameter index, type_name and status; `Message` holds the canonical generated (Domain,SubDomain,String) identity, diagnostic declaration and its ordered `Parameter` tuple; `DiagnosticSchema` holds the exact generated fingerprint/digest, issued message map and whether an independently supplied artifact SHA-256 pin was matched; `DecodedArguments` holds one qualified `Message` and its exact decoded values.

Private `_unique_object` rejects duplicate JSON properties, `_reject_nonfinite` rejects invalid JSON tokens, and `_bounded_unsigned` enforces owner-defined finite unsigned fields. `load_generated_schema(data,max_source_bytes=2097152,max_messages=65536,trusted_artifact_sha256=None)` parses bounded generated schema JSON, validates finite count/type/identity/fingerprint constraints and, **only if a separately trusted pin is supplied**, compares the exact artifact hash in constant-time fashion where supported; a fingerprint alone is **not** an authenticated origin. `_argument_matches(kind,value)` tests values against the specified owner-defined exact kind; `decode_canonical_json_base64(value,expected_length=None)` enforces canonical URL/byte representation rather than accepting arbitrary encodings; `_json_argument` converts one governed positional JSON value under its declared kind; `decode_declared_arguments(...)` verifies the full positional count, generated message contract and exact value kinds from a typed envelope, without guessing missing historical schema facts. No C++ generator is reimplemented in this module; EDP-Localisation remains the schema owner.

## 9. `historical_schema.py` — optional archived Localisation provenance bridge

[Source](../tools/edp_logging/historical_schema.py). This optional module is activated only when the operator explicitly requests historical schema resolution; ordinary frame/record parsing does not import an archive catalogue unconditionally. Frozen `HistoricalTemplateEvidence` and `HistoricalDiagnosticEvidence` distinguish the exact selected original ContractFamily/translation evidence from the separately issued diagnostic schema identity. `load_archived_diagnostic_schema(...)` consumes the existing EDP-Localisation archival verifier and the bounded `schema.load_generated_schema` owner, rejects mismatched source hashes/family selection with `SchemaError` rather than substituting a current translation, and returns qualified historical diagnostic evidence only when exact identity/pins agree. A diagnostic fingerprint identifies an argument schema, **not** a language pack, civil timestamp, archived text or cryptographically authenticated producer. Read and cache the selected catalogue outside constrained firmware and keep the original build pin as a separate trust decision.

## 10. `analysis.py` — conservative finite ticket and time comparison

[Source](../tools/edp_logging/analysis.py). `MAXIMUM_UNCERTAINTY=0xffffffff` is the bounded Clock uncertainty sentinel used for comparisons. `EvidenceError` represents unsupported or over-capacity forensic analysis rather than a guessed result; `TemporalOrder` enumerates explicitly justified order relations (earlier/later/overlap/incomparable under each value's actual certified uncertainty). Frozen `AttemptEvidence` stores observed per-device/per-incarnation ticket range/count/gap facts; private `_identity(facts)` selects the exact strong source identity, and `_correlated_and_reliable(facts)` prevents time inference from an unsupported Clock quality. `analyse_attempts(...)` groups bounded observed source attempt counters, **not** lost-message counts: a gap may mean a dropped admission, corrupt record, missing capture, different filter or arbitrary export truncation. `compare_record_time(left,right)` compares only independent records with mutually qualified same-Era correlated synchronized coordinates and uncertainty intervals. Overlap is *not* a false total ordering, incomparable is *not* a timestamp of zero, and synchronized coordinate is **not** UTC/civil time. The command's max-analysis-records/groups/pairs settings must cap all computation/output.

## 11. `cli.py` — bounded command parser and JSONL forensic output

[Source](../tools/edp_logging/cli.py). `main(argv=None) -> int` is the one public CLI entry; it builds the argparse options for raw frame inspection, optional `--archive` EDLS/EDLC validation, optional canonical `--validate-record` LogRecord TypedEnvelope and facts, `--expected-root-type-hex` pin, optional `--diagnostic-schema`, historical catalogue provenance, bounded `--analyse-attempts` and `--compare-record-times`. Finite `--max-*` arguments constrain source bytes, records, groups, resynchronization, comparison count and output before unbounded work is attempted. It delegates all wire/schema/Clock checks to the owner-specific modules above, serializes evidence as JSONL with typed error records where appropriate, and uses a nonzero process status for input/validation failure. The current command implementation composes `record_structure`, `schema` and `record_facts` for its optional typed-record inspection; it is not an independent decoder or schema owner. A command reporting validated candidate facts is **not** NVS ACK, physical POR proof or guaranteed record delivery.

## 12. `export_csv.py` — conservative bounded JSONL → CSV presentation

[Source](../tools/edp_logging/export_csv.py). `COLUMNS` is the fixed, stable output column order for exactly the evidence categories selected by the forensic JSONL contract, not an arbitrary new field decoder. `CsvEvidenceError` represents unsupported/malformed/oversized evidence or invalid JSONL cells. Private `_safe_cell(value)` serializes limited typed fields and guards against spreadsheet-formula injection and unsafe text interpretation; it must not reinterpret unknown strings or data as verified identities. `export_stream(...)` incrementally reads caller-provided evidence with finite per-line limits, validates fields/types and emits conservative CSV rows, rather than accumulating an unbounded multi-record archive. `main(argv=None) -> int` supports standard file/stdin paths and `--max-line-bytes` bounded streaming with truthful nonzero error status. This is a *host-side presentation adapter*: no source LogRecord ID, Clock coordinate, translation or storage guarantee is added by exporting it, and no output row proves an independent NVS acknowledgement.

## Ownership, resource limits, exceptions and source traceability

All modules require only the host Python standard library, plus **optional** independently selected EDP-Localisation archival tooling for historical-resolution mode. Pure readers accept bytes/streams **borrowed during their call**, return immutable value objects or bounded iterators/evidence, and must not retain a live device file handle or silently mutate archive storage. `ValueError` and dedicated `EnvelopeError`, `SegmentHeaderError`, `SchemaError`, `RecordFactError`, `CsvEvidenceError`, and `EvidenceError` denote different rejection owners; the CLI maps these to user-visible typed results and nonzero termination when requested validation cannot complete. Each module's source code and maintained tests are paired under `tools/tests/` and the root `tests/` host integration suite. Future changes to a parser/CLI option/return shape must update **both** these Wiki sections and its normative `docs/` contract on the same branch. No module may claim an independent physical cut proof; such evidence remains in native RPI400 HIL receipts and G1–G15 acceptance.
