# G1 tracked lease ownership, RAII release-to-wake and strict tracked drain

**Status:** optional G1 milestone; `feature/logging-v1`, version **0.1.0**. This is not the complete Logging producer/FIFO or a reason to use EDP-Memory native finite ObjectPool acquisition.

## The optional contract

`src/logging/TrackedAdmissionCoordinator.hpp` introduces `TrackedAdmissionCoordinator<TProducerCount,TWaitWakeProvider>` with a private `AdmissionLifecycleCoordinator`, borrowing the same Bootstrap-selected **EDP-Threading BoundedWaitWake** provider (requires at least `TProducerCount + 1` stable slots, last slot reserved for the single shutdown drainer). It owns three lock-free counters: `_inflight` outer acquisition transactions, `_outstanding` **successfully granted tracked leases**, and `_unconfirmedReleases`, plus a `_wakeFailures` diagnostic counter. No dynamic allocation, owner-specific timebase, new EDP dependency, platform-concrete provider, independent queue or native finite EDP-Memory waiter.

A consumer constructs a `TrackedAdmissionCoordinator::TrackedLease<NativeObjectPoolLease> guard(coordinator)` (requires a default-constructible native lease). The raw EDP-Memory lease remains PRIVATE and cannot be moved/copied, manually destroyed or bypassed by an ordinary user of this opt-in API. `AcquireUntil<TMaximumWakeRetries>(producerSlot,pool,guard,canonicalAbsoluteMonotonicDeadline,args...)` validates coordinator identity and that the guard is empty before invoking the **existing G1 cancellation-aware NoWait/Threading WaitUntil** admission. Its return is `TrackedAdmissionResult {Validation,CoordinatedAdmissionResult}`: the validation enum distinguishes `Valid`, `WrongCoordinator`, `LeaseOccupied`; it never lies about the native grant status or notification-health result. Success, `GrantedAfterDeadline` and `GrantedDuringShutdown` ALL increment the outstanding tracked count while the native lease stays owned by the guard.

The outer `_inflight` reservation spans the handoff gap between the nested lifecycle admission's return and the tracked lease counter increment; a shutdown drainer cannot mistake that brief transition for no work. The nested G1 lifecycle's original in-flight count is still checked as well. Each outer exit wakes the reserved Threading drain slot after shutdown, using its original latching semantics.

`guard.Release()` is the ONLY explicit release API. It calls the real EDP-Memory lease `Release` through `AdmissionLifecycleCoordinator::ReleaseAndNotify`, decrements the outstanding counter only after native capacity return is positively confirmed, records notification failures independently, and wakes the shutdown drainer. If the caller forgets to release, the guard destructor performs this same native release-and-wake. **The scope destructor wakes blocked producers without caller intervention.**

### Native-destructor failure honesty

EDP-Memory's underlying move-only `ObjectPoolLease::~ObjectPoolLease` calls its own `Release()` and discards an error. Thus, when the new guard's destructor first attempts native release and receives `MemoryProviderFailure`, the later EDP-Memory member destructor could either succeed or fail **without exposing which**. The guard must not claim success or decrement its tracked count in that situation. It increments a **sticky `UnconfirmedReleases`** counter and leaves the outstanding count conservative. A trailing notifier member, declared BEFORE the native lease member and therefore destroyed **AFTER** the native destructor, performs a best-effort wake to all producer slots and the drain slot in case the native destructor did release previously blocked capacity. This is *not* evidence of successful capacity return or guaranteed wake; failures are recorded. A sticky uncertainty forces strict tracked shutdown to report `UnconfirmedNativeRelease` rather than false `Quiescent`. Recovery requires explicit application/system reconciliation; the current helper offers no invented success/reset API.

`ShutdownTrackedUntil<MaxDrainWakes>(oneAbsoluteEDPClockDeadline)` sets the same monotonic one-way shutdown flag and publishes producer wakes, then drains **outer in-flight acquisition transactions**, nested Lifecycle active admissions and all **tracked outstanding leases**, with one EDP-Threading WaitUntil and finite wake budget. It returns `TrackedDrainResult` containing strong status `Quiescent / DeadlineElapsed / WakeRetryLimitReached / DrainWaitProviderFailure / UnconfirmedNativeRelease`, independently captured shutdown wake-publication health, `ActiveAcquisitions`, `OutstandingLeases`, `UnconfirmedReleases`, `WakeFailures`. A clean status means *only* that all tracked `AcquireUntil` calls have exited, and every tracked lease was positively released; it does **NOT** mean other raw Memory leases, unjoined tasks or queues/sinks have drained. One exclusive drainer only.

## Strict unsolved gates and setup

- This API tracks only leases **obtained through its own `AcquireUntil` method**, not raw `AdmissionLifecycleCoordinator::AcquireUntil`, other directly acquired EDP-Memory leases or consumers of different pools. The application MUST exclusively use this owner path for all relevant grant/release operations before regarding `Quiescent` as a teardown prerequisite.
- A guard and its coordinator/Threading owner/MemoryTopology must retain strict parent-before-child lifetimes; Bootstrap MUST prevent new calls, wait for this successful tracked drain **and join every producer/consumer task** before destroying providers. A delayed task may still hold a live pointer even when the lease count is zero.
- The underlying Memory provider may fail its release. The design cannot prevent the underlying native destructor from retrying without reporting its outcome, but it conservatively refuses false success and issues a trailing best-effort wake.
- Capacity unfairness/FIFO, exact end-to-end deadline bounds of *all* underlying native operations, lost-wake proof under ESP32 FreeRTOS, multi-producer slot registration, physical target/HIL, EDP-System-governed LogRecord root, full queue/worker and archive remain open. Never call G1 solved merely because this optional guard works on host.

## Actual tests

`tests/TrackedAdmissionCoordinatorTests.cpp` and runner `tests/run-tracked-admission-tests.sh` use the **actual EDP-Memory host MemoryTopology**, pooled objects, platform Mutex/Signal and EDP-Threading BoundedWaitWake fixture (pinned versions). Tests verify exact 2-capacity pool real admissions and live objects, producer wake from **scope destructor alone** (no manual native release), earlier explicit release and partial wait handoff, unsuccessful attempt to reuse occupied guard, mismatched coordinator rejection before pool access, timeout while one tracked lease remains despite zero in-flight calls, strict clean shutdown after RAII release, and a native Mutex release failure followed by unobservable Memory destructor retry: sticky uncertainty refuses clean shutdown despite PooledObject live count reaching zero. Existing real G1 wake/owner failures and contention tests are included again.

Strict GCC+Clang tests **PASS** RPI400 detached `20261016T085118-8d57dc8a` (the first run `20261016T084951-fc3311a4` also passed before the additional destructor-wake scenario). No linked/physical ESP32 target was tested by this host execution.
