# EDP-Logging architecture — current implementation contract

**Source:** `feature/logging-v1`, version `0.1.0`, reconciled 1 November 2026. This document describes the currently implemented layers and their boundaries. The original D1–D13 design decisions and chronological experiments are retained in [Policy's architecture living handoff](https://github.com/ESPressio-Development-Platform/Policy/blob/main/Handoff/2026-10-15/2026-10-15-11-46-EDP-Logging-Architecture-Living-Handoff.MD). Current gate/evidence classification is in [G1–G15 acceptance](ACCEPTANCE-G1-G15.MD) and the [qualification ledger](LOGGING-QUALIFICATION-STATUS.MD). A release-wide production sign-off has **not** been made.

## Architectural ownership

Logging owns source-side diagnostic identity, captured bounded arguments, record assembly, attempt sequencing, EDLG/EDLS framing, bounded queue/worker/sink orchestration and strict EDLS transaction logic. It **does not** own a new generic memory allocator, platform task, mutex provider, universal clock, flash filesystem, CBOR encoder or diagnostic catalogue compiler.

- **EDP-System:** issued universal LogRecord root `TypeIdentifier`, strong field identity and compile-time Composition architecture. Fields 0–14 remain governed; no native object-memory dump is a portable wire encoding.
- **EDP-Memory / EDP-BoundedTopology / EDP-BoundedTypes:** finite pool lease ownership, queue slot topology and bounded byte/string resources; successful admission is RAM ownership, not durable acknowledgement.
- **EDP-Threading / EDP-Platform:** task, wait/deadline, mutex, wake and optional canonical atomic provider selection. One dedicated coordinator consumes the existing bounded queue, and its optional sink service flushes partial batches on the canonical deadline. No parallel queue, timer, allocator or task is introduced.
- **EDP-Clock:** the application-wide canonical monotonic coordinate for wait and flush deadlines, with optional qualified synchronized timestamp/ClockEra evidence; unavailable synchronized state is represented explicitly and not invented from local time.
- **Owned source byte copies:** the opt-in OwnedDiagnosticArguments owner uses the existing EDP-Memory CopyBytes capability through a compile-time-selected stateless provider, with EDP-Platform-Portable as default. The internal source replay also uses that provider. All source byte capacities remain compile-time bounded and no provider pointer/heap object is retained. The copying mutation operations are runtime, not constant-evaluated; inspectors retain constexpr eligibility. This is an optional concrete C++ provider only, not an SDK/native adapter or a default-umbrella dependency.
- **Strict UTF-8 source capture:** the opt-in OwnedDiagnosticArguments module reuses <serialisation/Utf8Validation.hpp>; AddUtf8 rejects embedded U+0000 in keeping with canonical CBOR/JSON and BoundedTypes::String. AddBytes retains arbitrary binary bytes when authorised by generated schema. The default Logging umbrella does not add this dependency.
- **EDP-Localisation / EDP-Serialisation:** generated diagnostic schema signatures, owned heterogeneous argument mapping and canonical CBOR/JSON codecs where supported. Diagnostic fingerprint is not a guarantee of exact historical natural-language wording.
- **EDP-Persistence and platform concretes:** application-selected FileStorage and independently qualified KeyValueStorage providers; Logging owns the protected-record verification and acknowledgement protocol, not native flash drivers or generic interruption-atomicity traits.

The public umbrella remains intentionally lightweight; heavy and platform-specific features are opt-in through the existing owner headers and application Bootstrap Composition. All memory/provider lifetimes must outlive their active claims and pending durable work.

## Record and execution lifecycle

An enabled site evaluates arguments exactly once and issues a nonwrapping, invalid-zero strong attempt ticket before capacity waiting. A generated-schema-governed source record captures the original typed values and original source coordinates in finite owned storage. The application-selected producer/queue coordinator handles finite admission, committed FIFO transfer, bounded worker quanta, typed encoding and separate per-sink accepted/retired/durable completion outcomes. A sink submission or queue retirement must never be reported as persistent acknowledgement.

The generated managed-worker fixtures demonstrate a full fifteen-field source record, canonical CBOR, sealed bounded EDLS segment publication and independent on-media replay. The application selects compile-time record/byte bounds and a permissible Bootstrap dwell; the first admitted record's deadline is not silently extended by later arrivals. Recovery-required uncertainty cannot be blindly retried or reclassified as success. The active worker drains and services the existing sink while respecting canonical Threading deadlines; application Bootstrap owns shutdown/teardown of all queues, worker contexts and native providers.

## Durable history and bounded storage

The strict PowerLossAcknowledgedEdls owner uses independently completed immutable segment candidates with complete header, record, seal/CRC and readback validation. A separately qualified NVS KeyValueStorage watermark is the acknowledgement authority. Protected older records are not retired until a complete successor is durably acknowledged and independently rechecked. A shortened, corrupted or ambiguous candidate remains unaccepted; the implementation must not invent a repair or autoformat on storage failure.

The application provides an immutable logical **byte** capacity during Bootstrap or before archive initialisation. The budget includes all reserved segment slots and the fixed ACK value, including temporary successor/pre-retirement bytes; it does **not** bound filesystem allocation metadata, NVS journal overhead, Flash erase blocks or unrelated writers. The application also chooses *where* storage resides. Separate storage is recommended for substantial release-build diagnostics. No operational-lifespan or Flash-endurance assurance is made, and generic LittleFS FileStorage replacement remains Restart-retained with **no interruption atomicity**.

## Validated and unvalidated scope

RPI400 GCC/Clang/UBSan owner tests, generated schema integrations, three build-target demonstrations and specified ESP32/WROOM physical tests have recorded bounded, finite successes. The 30,000-source five-minute profile offered 100 records/sec and completed all accepted records; a separate 28,000-byte logical-capacity profile recorded 27,088 bytes peak and protected-media readback. These are distinct tested profiles, not an indefinite service-life/throughput promise. GPIO17 externally verified cuts require physical controller OFF/ON/elapsed receipts, boot correlation and independently checked original protected data; reset codes alone do not establish success.

Open or conditional semantics include fully synchronized Clock+Era provider qualification, all serial concrete targets and output modes, exact historical presentation provenance, arbitrary interrupted provider GC/flash phases, unqualified target/resource configurations, and the complete application-specific product acceptance budget. Raw native LogRecord dumping is intentionally excluded. The opt-in owned diagnostic text validator reuses the existing EDP-Serialisation UTF-8 owner and rejects embedded U+0000; runtime byte-copy composes existing EDP-Memory ByteOperations. The default Logging umbrella retains its dependency-light C++20 contract.
