# Optional G3 ClockEra diagnostic argument profile

**Version 0.1.0**, `feature/logging-v1`, opt-in public header `<logging/DiagnosticClockEraArguments.hpp>`. The default `DiagnosticArgumentEncoding.hpp` maintains its existing dependency profile and does not import EDP-Clock or create a new strong type on its own.

The optional header first imports **EDP-Serialisation's** `<serialisation/ClockEraAdapters.hpp>`, which contains the owner-certified reversible `Clock::ClockEra` ↔ `uint64_t` canonical adapter, then specializes the internal `IsCertifiedDiagnosticClockEra<Clock::ClockEra>` trait. The existing Logging generated-schema checker therefore accepts `ClockEra` only for an **EDP-Localisation generated** `DiagnosticParameterKind::ClockEra` argument, and rejects an unqualified `uint64_t` or a different strong Type. Positional CBOR uses one canonical unsigned integer; JSON uses decimal. Both use the **existing** EDP-Serialisation measured transactional encoder.

**Conditional owner edges:** importing this Logging header activates EDP-Logging→EDP-Serialisation and EDP-Logging→EDP-Clock (abstract) with existing dependencies; it also activates the *optional* EDP-Serialisation→EDP-Clock header profile. This graph is acyclic; Clock does not import Serialisation, Logging or Mesh. The consuming application's Bootstrap must declare the actual EDP-Clock dependency, but this header does NOT select any platform Clock provider or Mesh root.

**Absolute temporal trust boundary:** Logging never mints or certifies a ClockEra. All-zero is an invalid/unavailable sentinel, even if canonically serializable. A nonzero value alone is NOT proof of genuine Clock Root, synchronicity, election, unique provenance or same-revision coherence; the G2 upstream Clock/coordinator source and `LogTemporalEvidence.hpp` must still supply those facts. G4's permanent LogRecord TypeIdentifier from EDP-System#11 remains outstanding. These two arrays are **diagnostic Field13 argument values**, NOT full typed LogRecords.

**Test:** `tests/run-diagnostic-clock-era-tests.sh` invokes the **real EDP-Localisation compiler** for a descriptor containing kind `clock-era` and verifies exact C++ kind mapping, rejection of raw uint64 and arity mismatches, exact 10-byte CBOR golden, JSON decimal golden, zero sentinel and transactional capacity failure. GCC/Clang and Xtensa syntax-only are source qualifications, not end-to-end Mesh synchronized timestamp or physical HIL. Existing G1/G2/G3/G5 owner and EDP-Serial downstream tests remain mandatory.
