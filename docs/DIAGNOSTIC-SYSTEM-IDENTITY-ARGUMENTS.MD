# Generated System identity diagnostic parameters (G3)

This optional G3 extension consumes **existing EDP-Localisation generated** parameter kinds `DeviceIdentifier` and `RuntimeIncarnationId`. Exact accepted C++ arguments are `EDP-System::Identity::DeviceIdentifier` and `EDP-System::Identity::RuntimeIncarnationId`; raw `uint32_t`, bounded `Bytes<16>`, arbitrary arrays, or a different strong type are NOT accepted as substitutes. EDP-Logging statically checks position/arity/kind, requires EDP-Serialisation owner `SerialisableType`, then delegates to its already qualified canonical CBOR/JSON value writers.

DeviceIdentifier encodes as canonical 16-byte CBOR binary string or RFC4648 Base64 JSON via **EDP-Serialisation::SystemIdentityAdapters**, with strict reversible size check on decode. RuntimeIncarnationId encodes as uint32 CBOR unsigned / JSON integer and remains a System-assigned durable incarnation rather than a raw application counter. Both invalid-zero sentinels remain reversible as wire values but **must be rejected by any LogRecord validity check**, never interpreted as real device/incarnation identity. No Logging encoder, arbitrary ID generation, Clock/Mesh concrete import, TypeIdentifier allocation, new library dependency, or wire revision was introduced. Version 0.1.0 unchanged.

The G3 value path is still only diagnostic **Field13**, not a completed typed LogRecord. G4 universal governed root TypeIdentifier awaits EDP-System#11. No ClockEra or Localisation width-parametric string identifier mapping is claimed. Tests use the actual Localisation compiler to generate `device-identifier`/`runtime-incarnation-id` schema and confirm canonical CBOR 23-byte frame, JSON Base64/integer, transactional size failure, exact generated type order/arity and negative compilation on mismatched kinds under GCC/Clang. Test runner: `tests/run-diagnostic-system-identity-tests.sh`.
