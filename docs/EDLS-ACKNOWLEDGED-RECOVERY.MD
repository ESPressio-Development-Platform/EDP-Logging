# PowerLoss-acknowledged finite EDLS rolling and unacknowledged candidate recovery

**V1 optional explicit application-composition contract**, all versions 0.1.0. This extends—not replaces—the existing bounded EDP-Logging immutable EDLS/EDLG code. Previously generated EDLS files without a matching committed acknowledgement ledger are **not eligible for automatic cleanup/migration**. Production may opt into the strict two-provider architecture by selecting the existing EDP-Persistence-ESP-IDF NVS KeyValueStorage **at Bootstrap**; Logging itself remains portable and binds only abstract EDP-Persistence FileStorage/KeyValueStorage.

## Proof boundary and exact ordering

`PowerLossAcknowledgedEdls<TPhysicalSlots,TProtectedSlots,TPayloadMaximum,TSegmentMaximum,TFileStorage,TKeyValueStorage>` is a synchronous, caller-serialised worker-side composition. It uses an externally supplied KeyValueStorage with compile-time **PowerLoss retention AND PowerLoss interruption atomicity**, declared read/write and at least 40-byte keys, plus existing (conservatively Restart/None/MayModify) FileStorage. The independent KeyValue watermark is a **40-byte existing CRC-validated EDLS v1 header** storing `Generation = acknowledgedGeneration + 1` and the same device/incarnation; genesis encodes ACK 0. No new codec or persistence abstraction introduced. This records a committed acknowledgement, not a second log archive.

1. `InitializeEmpty` requires **all** archive paths physically absent plus the NVS watermark absent. It refuses to infer provenance from legacy stored files.
2. `Publish` starts by verifying the ledger and physical ACKed archive window, recovering only demonstrably unacknowledged or retired paths. It writes a new full CRC-checksummed immutable EDLS generation to a previously physically absent filename using the **existing** Logging EDLS owner and FileStorage provider.
3. The new successor must be fully read back and every *still-ACKed* predecessor remains unchanged. Only then does the existing PowerLoss-atomic KeyValueStorage owner `StoreValue` commit and an independent `ReadValue` confirm the watermark. **Only after this** is the publisher permitted to return any status denoting acknowledgement or retire the old eligible predecessor.
4. On interruption before the KeyValue ACK advances, `Recover` checks exactly the latest N CRC-clean, identity/RuntimeIncarnation-matched acknowledged generations, confirms the persisted ACK twice, and may remove the one extra physical candidate **only from the unacknowledged successor position**. Unknown/missing/corrupt protected history, wrong ledger identity/incarnation, duplicate generation, multiple unexpected files, or IO failure fail closed without removal.
5. On interruption after ACK advances but before oldest retirement, a complete and contiguous N+1 history is reverified and the existing `FinishEdlsProtectedRollingRetirementWithScratch` may retire only the older generation, preserving the new latest N ACKed ones. All callers supply bounded scratch and physically exclusive archive/ledger owners.

**Important:** PowerLoss retention/atomicity is a *KeyValueStorage* provider contract only. No claim is made that a generic LittleFS FileStorage `ReplaceFile`, GC, deletion, physical reserve or flash wear is atomic/power-loss safe. An actual flash fault damaging already ACKed predecessors is still an unrecoverable data-contract failure; fail-closed refusal cannot reconstruct destroyed bytes. The strict writer is not compatible with other writers mutating archive files or the same KeyValue key, and cannot certify previously acknowledged data written without this ledger. `AcknowledgedPendingRetirement` means the newest generation is durably acknowledged but reclamation remains pending; continued writes require a successful `Recover`.

## Validation, initial host slice

`tests/EdlsPowerLossAcknowledgementTests.cpp` uses existing EDP-Memory, EDP-Persistence real POSIX VFS FileStorage, and exact strict-capability KeyValueStorage contract fake. It validates genesis, 4-generation finite rolling, zero-length interrupted candidate removal, unsuccessful NVS ACK leaving predecessors intact, complete-but-unACKed candidate disposal, corrupt acknowledged frame refusal, changing incarnation refusal, no migration from legacy unlabeled archive, and durable read faults fail closed. GCC, Clang, UBSan detached evidence in Policy living handoff. Actual physical ESP32-NVS/flash crash-window and wear qualification is a **separate mandatory acceptance gate**, not implicitly satisfied by host tests.
