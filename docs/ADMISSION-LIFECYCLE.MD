# G1 finite cancellation and admission-drain lifecycle (partial)

**Source:** `src/logging/AdmissionLifecycleCoordinator.hpp`, conditional-only `feature/logging-v1`, package `0.1.0`. This is a further G1 implementation milestone, **NOT** a fully safe producer, transactionally allocated FIFO, or complete application shutdown proof.

## Owner contracts and state

`AdmissionLifecycleCoordinator<TProducerCount,TWaitWakeProvider>` wraps the existing `AdmissionWakeCoordinator` and adds **only** fixed, lock-free C++20 atomic shutdown state plus a count of in-flight `AcquireUntil` invocations. Bootstrap supplies an EDP-Threading `BoundedWaitWakeProvider` (or equivalent) with **at least TProducerCount+1 independent slots**. Slots `[0,TProducerCount)` are reserved **one per producer Task**, and the final slot `TProducerCount` belongs exclusively to the single shutdown drainer. The provider, all tasks, and the MemoryTopology must outlive the coordinator. No application-owned heap, background task, polling sleep, private timeout clock, stack-linked Memory waiter, platform concrete or new dependency edge was introduced.

`RequestShutdown() noexcept` atomically sets a one-way stop flag **before** publishing a wake on all producer slots, even when publication of one slot fails. `AcquireUntil<MaxWakeRetries>()` counts each in-flight call, rejects new admissions after stop is observed, and uses **`AcquirePoolUntilGuarded`** with one exact canonical EDP-Clock absolute deadline. The guarded retry path checks stop before every Memory **NoWait** acquisition and immediately after every Threading wake, avoiding a new wait on a cancelled producer. An unavoidable late Memory grant racing stop is returned as `AdmissionWaitResult::GrantedDuringShutdown` **with the Memory lease still owned**; no silent disposal or incorrect deadline outcome is allowed. The prior unguarded `AcquirePoolUntil` public signature remains available and delegates with a constant-false stop predicate; current G1 callers still compile. Distinct `ShutdownRequested` and `GrantedDuringShutdown` results are additive strong enum members 10 and 11.

`ShutdownUntil<MaxDrainWakes>(oneAbsoluteDeadline)` signals stop then checks in-flight admissions, awaiting completion via the **existing EDP-Threading WaitUntil** on the dedicated drain slot. Every retiring admission after shutdown attempts a latched wake to that slot. The drainer has finite deadline, compile-time finite maximum wake/retry budget and independent `AdmissionShutdownResult {Status, WakePublication, ActiveAdmissions}`. Status values: `Quiescent`, `DeadlineElapsed`, `WakeRetryLimitReached`, `DrainWaitProviderFailure`. A failed producer wake publication is **not hidden** by the eventual drain state; if a thread remains active at deadline, quiescence is **never fabricated**. If the call fails or reports nonquiescent, the coordinator **must remain alive**, caller may retry once cause is handled, and tasks must be joined by application Bootstrap. The drain function is strictly **single-caller, nonreentrant**.

## Hard limitations and mandatory prerequisites

- This count tracks **in-flight admission function calls only**, **NOT** live Memory leases, LogRecord consumers, Threading worker lifetimes or task joins. Even a `Quiescent` result does **not** allow MemoryTopology teardown if any successful/late lease is still held. Application must stop issuing calls, join producer/worker tasks and explicitly return all leases before destroying coordinator, wait provider or Memory runtime.
- Fixed producer slot exclusivity and parent resource lifetimes are external Bootstrap obligations. Concurrent calls with the **same slot** are invalid. Shutdown does not cause outstanding Memory leases to be reclaimed.
- Normal Memory ObjectPoolLease RAII destruction bypassing `ReleaseAndNotify` still can strand a waiting producer. All releases must be paired with wake publication; automatic notification-safe lease ownership remains unfinished.
- Pool NoWait mutex contention may appear as CapacityUnavailable even with free capacity, and may reach the original deadline without an external wake. Full fairness/transactional queue entitlement (D2), lost-wake proof on all target Platform Signal implementations, provider operation latency, complete bounded shutdown and ESP32 physical HIL remain open.
- **No EDP-Memory owner code was changed.** The unsafe native *finite* ObjectPool Acquire stack-waiter hazard in EDP-Memory#14 remains; this helper never calls it.

## Real owner tests and execution

`tests/AdmissionLifecycleTests.cpp` includes the **actual EDP-Memory composed host fixture** (and executes existing coordinator regression functions), not a counterfeit object pool. It runs fifteen concurrent two-producer saturation/shutdown/drain cycles, verifies old leases remain live after admission quiescence then releases them and tears down Memory safely, tests post-shutdown admission rejection, invalid slots, deterministic Memory successful grant racing shutdown, failed wake + deliberately stalled producer where `ShutdownUntil` must report deadline not quiescence, retry after that producer finally retires, and separate notification failure evidence. `tests/run-admission-lifecycle-tests.sh` runs strict GCC/Clang C++20 against six pinned abstract EDP dependency roots. Both PASS on RPI400 detached **20261016T082446-9a9fb25f**. This is a HOST test, not physical or firmware evidence.

## Composed queue transaction shutdown extension

The public TrackAdmission() method returns a noncopyable RAII admission scope, covering the complete queue wait, subsequent native Memory NoWait admission and rollback. The inner AcquireUntil scope also counts its own Memory subcall. A queue-stage producer is therefore represented in ActiveAdmissions so ShutdownUntil cannot report Quiescent while it is waiting to reserve a queue slot. PublishCapacityAvailable() forwards to the preexisting AdmissionWakeCoordinator bounded producer wake fanout whenever an empty pre-Memory reservation releases a queue slot. No additional Signal or waiter registry is created. Draining active calls is NOT a substitute for application task join, source record drain, sink callback completion or confirming all Memory leases returned. See [composed bounded record admission](BOUNDED-RECORD-ADMISSION.MD) and TestShutdownTracksQueueWaitingProducer.
